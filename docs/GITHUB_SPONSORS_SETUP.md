# GitHub Sponsors setup for MailFlow

This file contains ready-to-use copy for the maintainer's personal GitHub Sponsors profile. It is documentation only and does not create contractual obligations.

## Profile introduction

MailFlow is an independent, privacy-focused open-source AI email project. I develop it in my spare time with a strong focus on self-hosting, local and hosted LLM support, security, multi-user workflows, and practical automation.

If MailFlow saves you time, you use it regularly, or your organization relies on it, you can support continued development here.

Sponsorship helps cover development time, CI and test infrastructure, compatibility testing, security work, domains, tooling, documentation, and localization.

MailFlow remains open source under AGPL-3.0 regardless of sponsorship. Sponsorship is voluntary and does not create a support contract, SLA, guaranteed feature delivery, priority bug fixing, proprietary license, or ownership interest in the project.

Thank you for helping keep independent, privacy-focused AI tooling moving forward.

## Suggested goal

Start with a modest recurring goal:

**€100 / month**

Suggested description:

> Helps cover recurring project infrastructure, testing, domains, and development tooling for MailFlow.

Increase the goal only when recurring costs or the sponsor community justify it.

## One-time sponsorships

Enable one-time sponsorships if GitHub Sponsors offers them for the account.

Suggested wording:

> Prefer a one-time thank-you instead of a recurring sponsorship? One-time support is equally appreciated and helps fund MailFlow development and infrastructure.

## Public recognition

Do not make public recognition mandatory. Suggested wording:

> Sponsors may be acknowledged publicly if they want to be. Anonymous sponsorship is equally welcome.

If a sponsor explicitly opts in, their name or organization may be added to `SPONSORS.md`.

## Guidance for organizations

Suggested wording:

> Does your organization use MailFlow? Consider sponsoring the project to support the maintenance, security work, testing, and infrastructure your deployment benefits from.

Avoid promising response times, roadmap priority, consulting, support hours, or guaranteed implementation in exchange for sponsorship. Those would be separate services and should be handled separately if ever offered.

## Tax wording

Do not describe sponsorship as a tax-deductible charitable donation and do not promise donation receipts.

Use terms such as **support**, **sponsorship**, or **funding of continued development** instead.
